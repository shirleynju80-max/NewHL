# 自愿打赏设计文档

更新时间：2026-06-01

## 目标

在不接支付系统、不做会员权益、不增加运营复杂度的前提下，给「价值底仓配置台」增加一个轻量的自愿支持入口。

本功能只表达：

- 用户如果觉得工具有帮助，可以自愿打赏支持维护。
- 打赏不解锁额外功能，不影响现有功能使用。
- 打赏不是投资咨询服务、不是会员订阅、不是购买策略信号。

## 不做什么

第一版明确不做：

- 不接微信支付 / 支付宝支付接口。
- 不做订单、回调、退款、发票、自动对账。
- 不做登录、会员、权限、访问码。
- 不做“打赏后解锁完整表格 / 盘中监控 / 策略回测”。
- 不做打赏排行榜、付费社群、付费问答。

## 推荐入口

### 入口位置

建议放两个轻入口：

1. 顶部导航右侧：`支持项目`
2. 页脚或关于区：`自愿支持`

不要放在策略结果、买卖状态、产品详情关键判断旁边，避免让用户误解为“付费可获得更强信号”。

### 入口形态

优先使用弹窗，不新开重页面：

- 点击 `支持项目`
- 弹出一个小 modal
- 展示说明文案 + 微信 / 支付宝二维码
- 用户自行扫码
- 关闭弹窗后回到当前页面

也可以保留一个独立路由 `/support`，但第一版不是必需。

## 弹窗内容

### 标题

```text
自愿支持项目
```

### 主文案

```text
这个工具会保持基础功能免费。如果它帮你节省了研究红利、现金流、低波动 ETF 的时间，可以自愿打赏支持后续维护。
```

### 二维码区

建议两个并列卡片：

```text
微信支持
[微信收款码图片]

支付宝支持
[支付宝收款码图片]
```

移动端改为上下排列。

### 说明文案

```text
打赏完全自愿，不解锁额外功能，也不影响任何页面使用。
```

```text
本工具仅提供数据整理、回测和观察视图，不构成投资建议。
```

### 关闭按钮

```text
稍后再说
```

不建议使用“立即支付”“开通”“购买”等强交易词。

## 视觉设计

保持现有深色金融界面，不做营销页风格。

### Modal

- 宽度：桌面 `420-520px`
- 移动端：宽度 `calc(100vw - 32px)`
- 背景：`--fin-panel`
- 边框：`1px solid var(--fin-border)`
- 圆角：沿用现有面板圆角
- 阴影：轻微即可，不做强发光

### 二维码卡片

- 使用中性边框卡片
- 二维码背景保持白色，保证扫码识别
- 卡片内不要使用大面积强调色
- 支付方式名称用普通文本，不做按钮态

### 触发按钮

顶部导航里的 `支持项目` 应为次级按钮或普通链接：

- 不使用主 CTA 样式
- 不使用红色、金色、强渐变
- 不盖过核心产品导航

## 文案边界

### 可以写

- “支持项目持续维护”
- “自愿打赏”
- “基础功能保持免费”
- “不解锁额外功能”
- “不构成投资建议”
- “感谢支持”

### 不要写

- “付费后解锁”
- “会员权益”
- “付费获得买卖点”
- “付费查看完整策略”
- “保证收益”
- “跟随信号操作”
- “投资建议”
- “内部策略”

## 资源放置

建议新增：

```text
public/support/wechat-donation.png
public/support/alipay-donation.png
```

图片要求：

- PNG 或 WebP
- 单张建议小于 300KB
- 不要把个人敏感信息写进源码注释
- 文件名不要包含真实姓名或手机号

如果暂时不想提交真实二维码，可以先放占位图，部署前替换。

## 实现建议

### 组件

建议新增：

```text
src/components/SupportDonationModal.tsx
```

职责：

- 管理弹窗展示
- 展示说明文案
- 展示两个二维码
- 支持 Esc / 遮罩 / 关闭按钮关闭
- 移动端可滚动

### 入口接入

建议在 `Layout.tsx` 顶部导航接入：

```text
支持项目
```

点击后打开 modal。

不要在 `Home.tsx` 首屏做大横幅；首页仍然优先回答“长期底仓怎么配”。

### 状态

第一版只需要本地 React state：

```text
const [supportOpen, setSupportOpen] = useState(false)
```

不需要 localStorage，不需要记录用户是否关闭过。

- [ ] 点击后弹出二维码 modal。
- [ ] 文案明确“自愿打赏，不解锁额外功能”。
- [ ] 页面没有出现“会员”“开通”“购买”“解锁权益”等词。
- [ ] 二维码在桌面和移动端都能完整显示，不溢出。

- [ ] `npm run build` 通过。

## 后续可选演进

只有在自愿打赏有稳定反馈后，再考虑：

- 独立 `/support` 页面，展示维护说明和更新日志。
- 自愿填写反馈表单。
- 项目支出 / 数据维护说明。

仍不建议把本功能自然演化成会员系统；如果未来要做会员，应另起设计文档，单独评估支付、权限、备案和合规边界。
