# 价值底仓配置台：产品改版方案

更新时间：2026-05-21  
状态：产品框架讨论稿，可作为 Cursor / Codex 后续 UI 改版依据  
核心原则：先保证产品逻辑准确、自洽；数据细节分为“当前已有”和“后续补充”

## 1. 产品定位

**网站名称**：价值底仓配置台

**副标题**：从“现金创造”与“股东回报”两个维度，筛选长期底仓指数与产品

**一句话定位**：

> 这是一个面向长期配置型用户的价值底仓观察工具。它不以短期收益排名为核心，而是从企业“能否持续创造现金”和“是否愿意回报股东”两个维度，帮助用户理解、筛选并落地适合长期持有的指数和产品。

## 2. 核心叙事：同一根藤上的两朵花

长期底仓配置的底层问题不是“哪个 ETF 最近涨得多”，而是：

- 企业是否持续创造现金？
- 企业创造出来的现金，是否以合理方式回报股东？
- 当前价格、股息率、利差和风险水平，是否支持长期配置？

因此，网站采用“两朵花”框架：

| 维度 | 含义 | 对应指数/产品 | 用户问题 |
|------|------|---------------|----------|
| 现金创造 | 企业通过主营业务产生自由现金流，是价值的源头 | 自由现金流指数 / 现金流 ETF | 企业是否有真实造血能力？ |
| 股东回报 | 企业将现金以分红等方式返还给股东，是价值兑现的一种可观察方式 | 红利指数 / 红利 ETF | 企业是否愿意把现金回报给股东？ |

需要保持表述严谨：

- 红利不是自由现金流释放的全部，只是其中最可观察、最稳定的一种形式。
- 现金流指数不等同于红利指数，也不是红利指数的附属品。
- 两者不是简单替代关系，而是价值投资框架下的两个互补观察角度。

首页核心文案建议：

> 长期持有的底气，来自企业持续创造现金的能力，和愿意回报股东的意愿。  
> **现金创造**观察企业主营业务产生自由现金流的能力，是价值的源头。  
> **股东回报**观察企业将现金以分红等形式返还给股东的行为，是价值兑现的一种可观察方式。  
> 本网站从这两个维度，帮助你观察值得长期关注的指数和产品。

数据诚信声明建议：

> 自由现金流相关数据仍在完善中，当前版本主要展示历史表现、回撤及产品信息。红利维度基于股息率与国债利差给出配置参考。

## 3. 目标用户与使用场景

核心用户：

- 希望用红利、现金流、低波、质量等价值因子构建长期底仓的用户。
- 不希望只看短期 ETF 排名，而是希望理解配置逻辑的用户。
- 需要在 A 股红利、港股红利、现金流等产品之间做长期配置取舍的用户。

典型问题：

- 当前更值得看“现金创造”还是“股东回报”？
- 红利指数现在的股息率和股债利差是否有吸引力？
- 自由现金流指数适合作为哪类底仓？
- 同类 ETF 差异不大时，应该按什么维度选择产品？
- 哪些指数/产品数据完整，哪些还在待接入状态？

## 4. 产品故事线

新版网站的故事线应从“产品列表”切换为“配置理解”：

1. **理解价值底仓框架**
   - 价值底仓 = 现金创造 + 股东回报。
   - 自由现金流看“创造”，红利看“回报”。

2. **判断两个维度当前状态**
   - 现金创造：先看长期表现、回撤、产品可得性和数据完整性，不做估值时机判断。
   - 股东回报：可基于股息率、国债收益率和利差分位判断配置窗口。

3. **选择具体指数风格**
   - 现金创造：自由现金流相关指数。
   - 股东回报：A 股红利、港股红利、低波红利、红利质量、央企红利等。

4. **落到可投资产品**
   - 红利 ETF / 现金流 ETF / 场外基金。
   - 不做同类短期收益排名，重点展示跟踪指数、成立时间、数据状态，后续补规模、费率、流动性。

## 4.5 产品分层（配置 vs 策略）

网站是**两层结构**，不要混成一种产品：

| 层级 | 角色 | 典型用户 | 本站在这一层做什么 |
|------|------|----------|-------------------|
| **配置层** | 长期底仓：现金创造 + 股东回报 | 以长期持有、定投、底仓配置为主 | 首页「两朵花」、指数研究、产品落地；回答「配什么、为什么值得长期看」 |
| **策略层** | 在底仓之上叠加交易规则，**可含择时** | 规则交易、参数研究、需要盘中标尺的执行者 | 策略研究（回测/参数/观测）、盘中观察（标尺与提醒）；回答「用什么规则、历史上是否站得住、当下处于规则哪一侧」 |

要点（与用户对齐）：

- **红利、现金流类资产本身适合长期持有**——这是配置层叙事，不是否定择时。
- **交易策略可以带择时加持**——MA/RSI/布林、利差窗口、分位标尺等属于策略层能力，面向愿意主动管理节奏的投资者。
- **不同类型投资者并存**：有人只用到配置层；有人配置定好后，再用策略层做加仓节奏、减仓纪律或研究对照。
- 站点**不以首页推销短线买卖点**；策略层提供研究与执行辅助，**不构成投资建议**，由用户自选规则与风险承受。

文案边界建议：

> 首页主线是长期价值底仓配置（现金创造 + 股东回报）。策略研究与盘中观察面向「在底仓之上使用规则与择时」的投资者，用于回测验证与执行参考，不替代配置判断，也不等同于官方买卖指令。

## 5. 页面信息架构

### 5.1 配置总览

替代原“ETF总览”，作为网站首页。

首页首屏应回答：

- 网站为什么同时看红利和现金流？
- 当前两个维度分别处于什么状态？
- 哪些指数和产品值得继续查看？
- 当前数据有哪些缺口？

首屏模块：

1. 网站标题与副标题
2. “两朵花”框架卡
3. 双维度状态卡：现金创造 / 股东回报
4. 数据完整性提示

首屏之后：

1. 候选指数
2. 产品落地分组
3. 盘中观察入口
4. 策略研究入口

### 5.2 指数研究

替代原“了解指数”。

一级维度：

- 现金创造
- 股东回报

二级筛选：

- 市场：A 股 / 港股
- 风格：低波 / 质量 / 央企 / 自由现金流

列表不应做简单收益排名。更合理的展示字段：

- 指数名称 / 代码
- 所属维度
- 风格标签
- 全样本 / 近 3 年 / 近 5 年表现
- 最大回撤
- 最新股息率与利差（仅红利维度或有数据时展示）
- 数据状态
- 主跟踪产品

### 5.3 产品落地

可由当前 ETF 总览改造，或后续拆成独立页面。

产品分组：

1. 现金创造类 ETF
2. 股东回报类 ETF：A 股红利
3. 股东回报类 ETF：港股红利
4. 场外基金 / 待完善产品

展示原则：

- 不做 ETF 历史收益排行榜。
- 同类 ETF 的收益差异多来自成立时间、费率、跟踪误差、流动性和样本期，不应放大为“优劣排名”。
- v1 展示代码、名称、跟踪指数、成立时间、数据状态。
- v2 补规模、费率、成交额、跟踪误差、溢折价。

### 5.4 指数详情

保留现有研究页逻辑，但顶部增加一句结论：

- 现金创造类：强调历史表现、回撤、产品可得性和数据状态，不做配置窗口判断。
- 股东回报类：展示股息率、利差、历史分位和配置参考。

模块顺序建议：

1. 顶部结论与数据状态
2. 基本信息
3. 市场表现
4. 区间指标
5. 股息率 / 国债 / 利差（有数据才展示）
6. 跟踪产品

### 5.5 盘中观察 / 策略研究（策略层）

这两个模块属于**策略层**，保留完整能力，但不抢首页「两朵花」配置叙事。

- **盘中观察**：对已纳入监控的标的，按所选策略展示标尺、区间提醒与模拟价下的指标位置；服务**执行节奏**与**当下状态**，可支撑择时型投资者，文案避免写成「官方今日必买/必卖」。
- **策略研究**：网格回测、训练/验证划分、参数观测列表；服务**规则是否历史上可用、参数是否过拟合、多策略对照**；既适合长期纪律（低频、少换手），也适合主动管理（多参数、分位择时），由用户自选用法。

与配置层的关系：

- 先配置层定「配什么底仓」（红利 / 现金流指数与产品）。
- 再策略层定「怎么管节奏」（持有、定投、规则加仓、分位进出等）。

不建议的表述：

- ~~策略研究 = 仅纪律校验、禁止择时~~（过窄，与产品能力不符）

建议的表述：

- 策略研究 = **规则与择时的研究台**（回测 + 观测 + 对照买入持有）
- 盘中观察 = **执行态仪表盘**（标尺与提醒，非单向荐股）

## 6. 首页双卡片设计要求

### 6.1 现金创造卡

标题：现金创造  
副标题：自由现金流指数

核心解释：

> 自由现金流指数关注企业主营业务产生现金的能力，适合作为观察长期质量底仓的入口。当前版本先展示历史表现、回撤和产品可得性，暂不作估值时机判断。

v1 可展示：

- 代表指数：国证自由现金流、中证全指自由现金流、富时中国 A 股自由现金流聚焦
- 近 3 年 / 近 5 年年化
- 最大回撤
- 主跟踪产品
- 数据完整性：例如 2/3 有行情
- 状态文案：质量底仓候选

不要在 v1 展示：

- 配置窗口
- 自由现金流率
- FCF Yield 分位
- 盈利增长贡献

这些需要后续数据支持。

### 6.2 股东回报卡

标题：股东回报  
副标题：红利指数

核心解释：

> 红利指数观察企业以现金分红等方式回报股东的能力。当前股息率相对国债利差可作为红利资产性价比的参考。

v1 可展示：

- 代表指数：中证红利低波动、中证红利、上证红利等
- 最新股息率
- 国债收益率
- 股债利差
- 利差历史分位
- 配置观察：配置窗口 / 中性观察 / 警惕区
- 主跟踪产品

配置观察逻辑沿用现有利差规则：

- 配置窗口：
  - 利差 >= 2.5%
  - 或股息率 >= 5.5% 且利差 >= 1.5%
- 中性观察区：
  - 1% <= 利差 < 2.5%
- 警惕区：
  - 利差 < 1%

页面文案中不必暴露全部阈值，只在说明/tooltip/解释区呈现。

## 10. Cursor / Codex 协作建议

Cursor 重点：

- 根据本方案重构首页和指数研究页 UI。
- 处理响应式布局、视觉层级和交互体验。
- 做本地浏览器验收。

Codex 重点：

- 维护本产品文档和数据口径。
- 整理现有数据可用性。
- 补小范围逻辑、标签、分类、数据状态。
- 避免重复部署或覆盖 Cursor 的大块 UI 改动。

### 10.1 不重复工作的文件边界（执行期）

为避免互相覆盖，按“页面框架”和“数据逻辑”分层：

- Cursor 主改（页面框架与交互）：
  - `src/components/Layout.tsx`
  - `src/pages/Home.tsx`
  - `src/pages/IndicesListPage.tsx`
- Codex 主改（口径/分类/helper/文案常量）：
  - `src/lib/*` 下新增或调整 helper（如分类、状态标签、完整性统计）
  - `src/data/*` 中与口径相关的解析与聚合
  - `docs/product-redesign.md`、`docs/project-status.md`

约束：

1. Codex 不主动改 Cursor 正在重构的三大 UI 文件（除非被明确指派）。
2. Cursor 不改 Codex 新增的口径 helper（除非接口不满足 UI 需要并先沟通）。
3. 每轮只交付一个可验收目标，避免“同轮多页大改”。

### 10.2 串行实施顺序（无会议版）

1. Cursor 先完成 `Layout + Home` 的新定位首屏（两朵花 + 双维度状态）。
2. Codex 同步补“分类/状态/完整性” helper，确保 UI 取数口径稳定。
3. Cursor 再改 `IndicesListPage` 的一级维度与二级筛选。
4. Codex 补充数据状态文案、缺失说明和文档验收清单。
5. 最后统一 `npm run build` 验收；确认后再决定是否 push / deploy。

实现前请先确认：

- 当前工作区是否有未提交 UI 改动。
- 是否需要先由 Cursor 完成页面草图。
- 是否需要把“产品落地”作为独立页面，还是先放在配置总览页内。
