# UI 设计规范 + 文案术语表

> 目的：给「价值底仓配置台」一个**唯一的设计真相源**，挡住一轮轮 agent 各做各的造成的配色漂移、层级混乱、文案发散。
>
> 适用：任何改动 `src/index.css`、页面/组件视觉、或页面文案的人（含 AI agent）改前必读、改后按文末「验收清单」自检。口径与本仓库 `AGENTS.md`「产品设计：站在用户视角」一致。

---

## 0. 一句话原则

- **颜色少而有意义**：颜色只表达「语义状态」（涨跌/买卖/数据有无）；数据强调用**字重/字号**，不用颜色。
- **表面只分两层**：页底 + 卡片；更深的嵌套用**边线**，不要再填第三种灰。
- **文案回答「我能做什么判断」**，不暴露公式、字段名、根 K、网格、训练集这类「怎么算的」。
- **同一概念，全站一个词**（见 §6 术语表）。

## 1. 颜色系统

### 1.1 表面层级（最多 2 级）

| 角色 | token | 值 | 用法 |
|------|-------|----|------|
| 页底 | `--ft-bg` / `--fin-surface` | `#020617` | 全站背景，唯一最深色 |
| 卡片 | `--ft-card` / `--fin-panel` | `#0f172a` | 所有卡片/面板/表格容器 |
| 内嵌分隔 | —（不新增填充） | — | 卡片内再分区**用 `--ft-border` 描边或留白**，不要第三种底色 |

**现存违规 → 收敛目标**：

- `--ft-card-inner` 当前 `= #020617`（与页底同色），导致卡片内盒子像"挖洞"。
  目标：内嵌区**不要实心填充**；确需区隔用 `border: 1px solid var(--ft-border)` 或加 `padding`。`--ft-card-inner` / `--fin-panel-muted` 仅在「卡片直接贴在页底之外、需要一块比卡片更沉的输入区」时才用，且全站不超过 1 种。
- 禁止在页面里临时写 `bg-black/30`、`bg-white/5`、`#0b1220` 等**第三、第四种灰**。只能引用上表 token。

### 1.2 强调色 / Accent（唯一一个）

| 角色 | token | 值 | 用法 |
|------|-------|----|------|
| 主强调（唯一） | `--ft-accent` / `--fin-blue` | `#4f7df3` | 主按钮、链接、当前激活态、可点击的代码 |
| 主强调-弱底 | `--fin-blue-soft` | `rgba(79,125,243,.12)` | 激活 chip / 选中行底色 |
| 装饰紫（仅装饰） | `--fin-accent` | `#9b7eff` | **仅**顶栏那条渐变细线等纯装饰；**禁止**用于链接、数字、可点击元素 |

**现存违规 → 收敛目标**：

- 链接/「详情」类文字当前偏靛紫，和导航蓝不是一个色 → **全部统一到 `--ft-accent` 蓝**。
- `--ft-accent-grad`（蓝→紫渐变）**不得**用在按钮、链接、文字等交互元素；如需保留仅限装饰线。
- 数字（如「20 个 / 46 只」「行情价」）**不要**染蓝；用字重区分。蓝色只留给「可点击」。

### 1.3 语义色（只表达状态，不滥用）

| 语义 | token | 值 | 弱底 |
|------|-------|----|------|
| 正向 / 上涨 / 买侧 / 数据已接入 | `--fin-up` | `#8cd4a5` | `--fin-up-soft` |
| 负向 / 下跌 / 风险 / 卖侧 | `--fin-down` / `--fin-red` | `#f87171` | `--fin-down-soft` |
| 提示 / 待确认 / 临近 | `--fin-amber` | `#fbbf24` | `--fin-amber-soft` |
| 中性 / 无数据 | `--ft-muted` `#8f95a3` 描边/灰 | — | — |

**现存违规 → 收敛目标**：

- **三个绿合并成一个**：`--ft-good`、`--fin-up`、`--fin-teal(#34d399)` 含义重叠 → 统一用 `--fin-up (#8cd4a5)`。`--fin-teal` 仅作历史别名，新代码不要再引用，逐步替换为 `--fin-up`。
- 语义色**只**用于状态标签、涨跌数字、买卖区间；不要拿绿色/红色当普通装饰。

## 2. 标签 / Chip 规格（只允许三类）

所有 tag / chip / 状态徽标收敛为三种，统一 `border-radius: var(--ft-radius)`、`padding: 1px 6px`、`font-size: 10–11px`：

| 类型 | 底色 | 文字/边 | 用在 |
|------|------|---------|------|
| 中性 neutral | 透明 + `--ft-border` 描边 | `--ft-muted` | 「主产品」「2 套参数」「暂无数据」等无方向信息 |
| 正向 positive | `--fin-up-soft` | `--fin-up` | 「偏近买」「数据已接入」「优选」 |
| 提示 warn | `--fin-amber-soft` | `--fin-amber` | 「临近」「待确认」「成立不足 3 年」 |

- 禁止再发明实心绿/实心蓝/描边紫等第四种样式。
- 同一页里标签形状必须一致（圆角、内边距、字号一致）。

## 3. 排版与层级

- **字号阶梯**（够用即可，不要每处自定义）：页标题 `text-2xl`；区块标题 `text-base font-bold`；正文 `text-sm`；表格/次级 `text-xs`；脚注/代码 `text-[10px]`。
- **表格首列是锚点**：标的/指数名称列字重 `font-medium`、颜色 `--ft-text`；其余列默认 `--ft-muted`。**关键判断列**（如区间状态、卡玛、股息率）允许加重或用语义色，让眼睛有落点。
- **次级代码**（ETF/指数代码）最低对比度用 `--ft-dim (#6a7080)`，不得再更淡；可点击的代码才染 `--ft-accent`。
- 同一表格内**不要全列同字号同灰**——至少首列与 1 个关键列要在字重/字号上分层。

---

## 4. 间距 / 页头版式（跨页统一）

- **页头摘要统一一种版式**：标题 + 一句话说明（≤1 行）+ 一行「关键指标 pill」。不要这页用 banner、那页用 4 个 tile、另一页用两条细 summary 条。
- **筛选栏按组分行**：维度 / 市场 / 成立时间 / 时间窗等每组前加弱标签（`--fin-nav-group-label` 风格），组间留白或换行；**禁止**十几个 chip 挤一行用「|」硬分。
- 卡片间距统一（建议 `gap-4` / `gap-6`）；解释性长文移到对应研究页或折叠区，不要堆在标题下。

---

## 5. 图表

- 阈值/区间色块必须有图例说明用途；解释成本高就删色块或改简短图例。
- 网格线用 `--ft-border`；涨跌用 §1.3 语义色；不要为单图临时调色。

## 6. 文案术语表（全站统一用词）

### 6.1 统一用词（左边是标准词，右边是**禁止再混用**的同义说法）

| 标准词 | 含义 | 不要再写成 |
|--------|------|-----------|
| 监控策略 | 在盘中监控/列表中持续跟踪的策略 | 已登记策略、登记参数、注册策略 |
| 监控标的 | 被监控的 ETF | 已登记标的 |
| 回测 | 历史区间上的规则验证 | 训练、网格搜索结果 |
| 分位 | 指标在区间中的相对位置 | 标尺%、percentile、分位数（口语保留「分位」二字即可） |
| 买侧 / 卖侧 / 中性 | 当前信号方向 | 偏近买可保留；勿用 BUY/SELL 英文裸词 |
| 成立时间 | 指数/产品起始 | 首交易日（产品层可保留「首交易日」，指数层用「基日/成立」） |
| 股息率 / 利差 | — | div_yield、yield spread 等英文/字段名 |

> 同一概念在不同页面必须用同一个词。新增文案前先查本表；本表没有的新概念，先在此登记再用。

### 6.2 UI 禁止出现（面向用户的页面）

- **公式串**：如「夏普(simple)=年化/年化波动」「卡玛=年化/最大回撤」→ 移到帮助/说明折叠区，正文只给结论。
- **实现细节**：`public/data`、`CSV`、内部字段名、`/api/bundle`、「根 K / 日 K」、「参数网格(RSI/布林/MA)」、「训练集占比」。
- **裸缩写**：卡玛、夏普等首次出现需有一句人话解释或 tooltip，不能只甩「卡玛↓」。

### 6.3 链接 / 按钮文案规范

- 统一「动词 + 对象」或「对象」二选一并贯穿：如详情类一律「查看详情」或一律「详情」，不要「详情 ETF / 指数详情 / 产品详情」三种并存。
- 主操作按钮用明确动词（「执行回测」「查看精选跟踪」）；次操作弱化为文字链接。

### 6.4 必须对用户可见的声明（合规）

- 策略层内容必须标明**回测/监控、不构成投资建议**。
- 代理数据（用 ETF 行情代指数）页面必须**显式注释**。
- 用样例数据兜底时必须提示**非真实行情**。

## 7. 验收清单（改完自检）

- [ ] 没有引入第 3 种背景灰；内嵌区用边线/留白而非新填充。
- [ ] 没有新的链接/数字染色违规；蓝色只给「可点击」，紫色只在装饰线。
- [ ] 涨跌/买卖/有无数据只用 §1.3 语义色；绿色只用 `--fin-up`。
- [ ] 新增标签属于 §2 三类之一，且与同页其它标签形状一致。
- [ ] 表格首列加重、至少 1 个关键列有层级；次级代码不低于 `--ft-dim`。
- [ ] 页头版式与其它页一致；筛选栏按组分行。
- [ ] 文案过了 §6 术语表；无公式/字段名/根 K/网格/训练集等实现词。
- [ ] `npm run build` 通过；改了浏览器可见 UI 的，本地开页面复查目标元素生效。
